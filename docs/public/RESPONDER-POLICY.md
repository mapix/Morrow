# 响应器的来源与执行策略

## 创建时必须明确

1. 一个收信邮箱和该邮箱下的来源文件夹。
2. 完整的发件邮箱白名单，最多50个地址。邮箱地址精确匹配，不接受空白、仅域名或通配符。
3. 处理要求、回复写法、自动发送或仅保留草稿，以及每天响应上限。
4. 工具能力、工具网络域名白名单、Agent轮数、调用次数和执行时间预算。

默认用接收服务商的 DMARC 结果验证发件域名。Gmail 使用 `mx.google.com`；DMARC验证的是域名，不是个人身份。若选择仅地址白名单，应用会明确显示未验证发件身份。两种方式均拒绝不唯一的 From、手工导入资料和缺少服务商来源标识的消息。

## 默认策略

| 项目 | 默认行为 |
|---|---|
| 来源 | 已绑定邮箱、文件夹和明确邮箱地址列表 |
| 资料 | 触发邮件及其附件文本，不提供整个邮箱或其他聊天 |
| 工具 | 读取、附件读取、SRT沙箱脚本；能力可收窄 |
| 文件 | 只写本轮隔离输出和临时目录，结束后清理 |
| 工具网络 | 关闭；明确允许的域名仅可使用HTTPS443 |
| Agent | 最多6轮、10次工具调用、180秒 |
| 单条脚本 | 默认15秒；输出与文件写入都有预算 |
| 回复 | 处理与核对完成后回原From地址；不采用Reply-To，不抄送或密送 |
| 自动投递 | 10秒撤回窗口；每次发送前再次检查来源与规则版本 |
| 失败、越界、超预算 | 停止投递并保留执行记录，可由用户在原范围内重试 |
| 发送不确定 | 停止自动重试，等待核对已发送邮箱 |
| 防循环 | 跳过自己发出的邮件、退信、列表与自动生成/自动回复的邮件；同一来源只响应一次 |

固定正文也必须完成同一套 Agent 读取、工具执行和核对流程，不能绕过验证直接发送。策略修改会撤回尚未投递的自动回复；已经进入SMTP的尝试以实际服务器回执为准。

缺少明确来源的旧规则会暂停，等待重新设置。响应器执行目前在Mac上进行，需要Node.js22.12或更新版本及随应用打包的Anthropic Sandbox Runtime。
